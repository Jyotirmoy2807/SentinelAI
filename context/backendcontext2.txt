# SentinelAI Backend Master Context

## Part 2 — Governance Execution Graph, Shared State & Node Responsibilities

---

# Governance Execution Graph

The Governance Execution Graph is the heart of SentinelAI.

Every governance request executes inside a LangGraph workflow.

LangGraph is responsible only for orchestration.

Business logic always resides inside backend services.

The graph determines:

* Execution order
* Conditional routing
* Pause and resume
* Shared state propagation
* Failure handling
* Final response generation

The graph itself should remain deterministic.

---

# Shared Governance State

The entire workflow operates on a single shared object.

```text
GovernanceState
```

Every node reads from it.

Every node writes only its own section.

No node owns the complete object.

---

# GovernanceState Structure

```text
GovernanceState

request

metadata

identity

normalizedExecution

policy

firewall

risk

budget

compliance

approval

audit

execution

explainability

response
```

The object should be immutable wherever possible.

Nodes should update only their own fields.

---

# Request Section

Stores the original incoming request.

Contains:

* Raw request payload
* Request timestamp
* Client metadata
* Headers (if required)
* Correlation identifiers

This section never changes.

---

# Metadata Section

Contains generated platform metadata.

Example:

* Request ID
* Trace ID
* Workflow ID
* Graph Version
* Timestamp
* Execution Duration

Generated during API Ingestion.

---

# Identity Section

Written only by Agent Identity Node.

Contains:

* Passport ID
* Agent Name
* Department
* Owner
* Status
* Trust Score
* Reputation
* Allowed APIs
* Allowed Operations
* Policy Groups
* Budget Profile
* Risk Tier

No later node should reload this information.

---

# Normalized Execution

Stores the canonical enterprise intent.

Example:

```text
Service

Merchant

Operation

Refund

Parameters

Merchant ID

Amount

Reason
```

Every downstream node uses this normalized model.

---

# Policy Section

Owned only by Policy Engine.

Contains:

* Policy Evaluation Result
* Matching Policies
* Missing Permissions
* Violated Policies
* Final Decision

Other nodes may read it.

No other node modifies it.

---

# Firewall Section

Contains:

* Forbidden Operations
* Dangerous Prompts
* Restricted APIs
* Block Reason
* Firewall Decision

Firewall decisions are independent of policies.

---

# Risk Section

Contains:

* Numerical Risk Score

Example:

```text
0-100
```

Also includes:

* Risk Factors
* Risk Category
* Confidence
* Explanation

Risk does not approve.

Risk only evaluates.

---

# Budget Section

Contains:

* Budget Consumed
* Remaining Budget
* Transaction Amount
* Threshold
* Budget Decision

Budget engine never executes payments.

It only validates limits.

---

# Compliance Section

Contains:

* Compliance Rules
* Violations
* Regulatory Flags
* Internal Policy Flags
* Approval Requirement

Compliance never executes enforcement.

It only reports.

---

# Approval Section

Contains:

* Approval Required
* Approver
* Approval Status
* Timestamp
* Comments

Possible states:

Pending

Approved

Rejected

Expired

---

# Audit Section

Contains immutable governance history.

Includes:

* Audit ID
* Event Timeline
* Decision Trail
* Node History
* Timestamps

Audit data is append-only.

---

# Execution Section

Written only after governance approval.

Contains:

* Adapter Used
* Enterprise Request
* Enterprise Response
* Status Code
* Duration
* Retry Count

No governance node modifies execution.

---

# Explainability Section

Contains:

Human-readable explanation.

Example:

```text
Identity verified.

Policy P-102 matched.

Risk Score 18.

Budget available.

Compliance passed.

Execution approved.
```

Explainability never changes governance decisions.

---

# Response Section

Final output returned to the requesting agent.

Constructed only by Response Builder.

---

# Node Responsibilities

Each node owns exactly one responsibility.

---

# API Ingestion Node

Purpose

Receive governance requests.

Responsibilities

* Validate schema
* Create Request ID
* Create Trace ID
* Initialize GovernanceState
* Store original request

Never

* Execute governance
* Check policies
* Query database

---

# Request Normalization Node

Purpose

Convert heterogeneous requests into one canonical model.

Responsibilities

* Validate execution payload
* Normalize service names
* Normalize operation names
* Normalize parameters
* Populate normalizedExecution

Never

* Check permissions
* Call enterprise APIs

---

# Agent Identity Node

Purpose

Load Agent Passport.

Responsibilities

* Verify Passport exists
* Verify status
* Load permissions
* Load department
* Load trust score
* Load reputation
* Load budget profile
* Load policy groups

Output

Identity Context

Failure

Immediate denial.

---

# Policy Engine Node

Purpose

Enterprise authorization.

Checks

* Allowed Service
* Allowed Operation
* Department Rules
* Policy Groups
* RBAC
* ABAC
* Transaction Rules

Outputs

ALLOW

DENY

REQUIRE_APPROVAL

Never calculates risk.

---

# AI Firewall Node

Purpose

Detect unsafe requests.

Examples

Delete Database

Disable Audit

Shutdown System

Bypass Approval

Direct SQL

Restricted Enterprise Service

Firewall acts before expensive governance.

---

# Risk Engine Node

Purpose

Risk estimation.

Possible factors

* Monetary value
* Agent reputation
* Historical violations
* Sensitive resource
* Critical system
* Time of execution

Produces

Risk Score

Only.

---

# Budget Engine Node

Purpose

Financial governance.

Checks

* Daily Budget
* Monthly Budget
* Department Budget
* Transaction Limit

Outputs

Budget Result.

Never performs accounting.

---

# Compliance Engine

Purpose

Regulatory governance.

Examples

GDPR

PCI-DSS

SOC2

HIPAA

Internal Governance

Possible output

Require Human Approval.

---

# Human Approval Node

Purpose

Pause graph.

Store request.

Wait for reviewer.

Resume workflow later.

Approval system should not restart the workflow.

It resumes from this node.

---

# Audit Engine

Purpose

Create immutable governance records.

Every decision enters audit.

Audit cannot influence routing.

It is observational only.

---

# Enterprise Execution Node

This is the most important node.

It is the only node permitted to invoke enterprise adapters.

Responsibilities

* Select adapter
* Build enterprise request
* Execute API
* Capture response
* Store execution result

Never

* Evaluate policies
* Calculate risk
* Modify governance decisions

---

# Explainability Node

Purpose

Generate readable reasoning.

The explanation should answer:

Why was this request allowed?

Why was it denied?

Which policy blocked it?

What risk factors contributed?

What approvals were required?

This information powers the Explainability UI.

---

# Response Builder

Purpose

Construct standardized Governance API response.

Inputs

GovernanceState

Outputs

Governance Response

No business logic belongs here.

It performs transformation only.

---

# Architectural Invariants

The following rules must never be violated:

1. Every request must traverse the Governance Graph.

2. Enterprise APIs are callable only from Enterprise Execution Node.

3. Nodes never communicate directly.

4. Nodes communicate only through GovernanceState.

5. Business logic belongs in Services.

6. Database access belongs in Repositories.

7. Adapters isolate all enterprise integrations.

8. Explainability never affects decisions.

9. Audit never affects routing.

10. LangGraph owns orchestration, not business logic.
