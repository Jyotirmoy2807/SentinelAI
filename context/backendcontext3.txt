# SentinelAI Backend Master Context

## Part 3 — Backend Services, Repository Layer, Enterprise Adapter Architecture & Folder Structure

---

# Backend Layered Architecture

The SentinelAI backend follows a strict layered architecture.

No layer may bypass another.

```text
                FastAPI
                   │
                   ▼
          LangGraph Nodes
                   │
                   ▼
          Domain Services
                   │
                   ▼
          Repository Layer
                   │
                   ▼
             PostgreSQL

Enterprise APIs are completely separate.

          Enterprise Execution
                   │
                   ▼
          Enterprise Adapters
                   │
                   ▼
          External Enterprise APIs
```

Every layer has exactly one responsibility.

---

# Service Layer

The Service Layer contains all business logic.

It represents the business capabilities of SentinelAI.

Services never know about:

* HTTP
* FastAPI
* WebSockets
* LangGraph routing
* UI

Services operate only on business objects.

---

# Service Principles

Every service should:

* Have a single responsibility.
* Be stateless.
* Be independently testable.
* Use dependency injection.
* Never perform HTTP routing.
* Never return HTTP responses.
* Never call external APIs directly.
* Never perform UI formatting.

---

# AgentService

Purpose

Manages the lifecycle of AI Agents.

Responsibilities

* Register Agent
* Update Agent
* Suspend Agent
* Block Agent
* Activate Agent
* Delete Agent
* Load Agent Passport
* Manage Trust Score
* Manage Reputation
* Load Permissions
* Load Budget Profile
* Load Policy Groups

AgentService never evaluates governance.

# PolicyService

Purpose

Enterprise authorization.

Responsibilities

* Evaluate RBAC

* Evaluate Department Rules
* Evaluate Policy Groups
* Evaluate Allowed APIs
* Evaluate Allowed Operations

# FirewallService

Purpose

Protect enterprise systems from dangerous requests.

Responsibilities

* Detect forbidden operations
* Detect blocked enterprise services
* Detect dangerous prompts

Not hardcoded.

* Department

# Repository Layer

Repositories isolate persistence.

Repositories perform only CRUD.

Nothing else.

---

# Repository Principles

Repositories

* Never calculate business rules.
* Never evaluate policies.
* Never calculate risk.
* Never call enterprise APIs.
* Never invoke LangGraph.
* Never contain HTTP logic.

---

# Repository Structure

```text
AgentRepository

PolicyRepository

FirewallRepository

RiskRepository

BudgetRepository

ComplianceRepository

ApprovalRepository

AuditRepository

EnterpriseAPIRepository

ExecutionRepository
```

Each repository owns exactly one aggregate.

---

# Database Transactions

Services own transactions.

Repositories do not.

Example

```text
PolicyService

↓

PolicyRepository

↓

AgentRepository

↓

AuditRepository
```

The service coordinates multiple repositories.

# Enterprise Adapter Layer

The Adapter Layer isolates enterprise integrations.

SentinelAI should never depend on vendor-specific SDKs outside adapters.

---

# Adapter Architecture

```text
ExecutionService

↓

EnterpriseAdapterFactory

↓

RefundAdapter

↓

Enterprise API
```

Every enterprise integration implements a common interface.

---

# Base Adapter Interface

Every adapter should expose the same contract.

Example responsibilities

* Validate Request
* Transform Payload
* Authenticate
* Execute
* Handle Errors
* Normalize Response

This ensures ExecutionService remains vendor-independent.

---

# Example Adapters

```text
MerchantAdapter

BookingAdapter

InvoiceAdapter

PaymentAdapter

SAPAdapter

SalesforceAdapter

WorkdayAdapter

ServiceNowAdapter
```

Each adapter represents one enterprise capability.

---

# Adapter Factory

ExecutionService never instantiates adapters directly.

Instead

```text
ExecutionService

↓

AdapterFactory

↓

Correct Adapter
```

This enables dependency injection.

---

# Adapter Responsibilities

Every adapter should:

Translate governance request

↓

Transform payload

↓

Authenticate

↓

Invoke enterprise API

↓

Normalize response

↓

Return standardized result

No governance logic belongs inside adapters.

---

# Standard Execution Result

Every adapter should return the same structure.

Example

```text
Execution Result

Status

HTTP Code

Business Code

Payload

Latency

Retry Count

Raw Response
```

ExecutionService converts this into GovernanceState.

---

# Error Handling

Enterprise errors should never crash the graph.

Instead

Enterprise Error

↓

Execution Result

↓

Governance Response

The workflow always completes.

---

# Retry Strategy

Retries belong only inside ExecutionService.

Governance Nodes should never retry execution.

Possible retry conditions

* Network timeout
* Temporary service unavailable
* Rate limiting

Retries should use exponential backoff.

# Configuration

All configurable values should live outside source code.

Examples

* Database URL
* Redis URL
* Adapter Secrets
* Feature Flags
* Environment Variables
* Graph Configuration

No secrets should be hardcoded.

---

# Architectural Rules

The following rules are mandatory.

1. Nodes never access the database directly.

2. Nodes call Services only.

3. Services call Repositories.

4. Services never call FastAPI routes.

5. Repositories never invoke other repositories.

6. Enterprise APIs are accessed only through Adapters.

7. Adapters never evaluate governance.

8. Dashboard queries should never affect transactional tables.

9. Configuration must be externalized.

10. Every backend component must have a single, well-defined responsibility.
