# SentinelAI Frontend Master Context

## Part 3 — Component Architecture, State Management, API Integration, UI Standards & Development Guidelines

---

# Component Architecture

The frontend should be built using reusable components.

Components should be generic whenever possible.

Business logic should live inside feature modules.

Rendering logic should live inside components.

---

# Component Hierarchy

```text id="cmp001"
Application

↓

Layout

↓

Feature Module

↓

Feature Page

↓

Feature Components

↓

Shared Components

↓

Primitive Components
```

Every layer should have a single responsibility.

---

# Shared Component Library

Reusable UI components should live under

```text id="cmp002"
components/

button/

card/

badge/

table/

modal/

drawer/

tabs/

form/

input/

select/

textarea/

search/

pagination/

toast/

tooltip/

spinner/

skeleton/

timeline/

graph/

charts/
```

Shared components should never contain business logic.

---

# Primitive Components

Primitive components are UI building blocks.

Examples

Button

Input

Checkbox

Switch

Badge

Avatar

Tooltip

Icon

Divider

Typography

Spacing

These should remain generic.

---

# Composite Components

Composite components combine primitives.

Examples

Agent Card

Policy Card

Approval Card

Risk Badge

Governance Timeline

Execution Node

Audit Card

These may understand business concepts.

---

# Feature Components

Each feature owns its own components.

Example

```text id="cmp003"
modules/

agents/

components/

AgentTable

AgentForm

AgentHeader

AgentTimeline

AgentStatusBadge

AgentPermissionTable
```

These components should not be reused outside the module unless they become generic.

---

# Layout Components

Layout components define page structure.

Examples

Main Layout

Sidebar

Topbar

Content Container

Page Header

Section Header

Split Panel

Resizable Panel

They should never fetch data.

---

# React Hooks

Custom hooks encapsulate frontend logic.

Examples

```text id="hook001"
useAgents()

usePolicies()

useApprovals()

useDashboard()

useAudit()

useExecution()

useEnterpriseRegistry()
```

Hooks coordinate API calls and state.

---

# Hook Responsibilities

A hook may

Fetch data

Update data

Handle loading

Handle errors

Expose mutations

A hook should not render UI.

---

# React Query

React Query manages server state.

Every backend resource should have

Query

Mutation

Invalidation

Optimistic update (where appropriate)

Caching should rely on query keys.

---

# Query Keys

Use predictable query keys.

Examples

```text id="rq001"
agents

agent-details

policies

dashboard

audit

execution

approvals

enterprise
```

Avoid inconsistent naming.

---

# Zustand Store

Use Zustand only for application-wide UI state.

Examples

Sidebar Open

Selected Theme

Selected Agent

Current Filters

Selected Node

Open Drawer

Notification Queue

Never store server data in Zustand.

---

# Local Component State

Local state belongs inside components.

Examples

Current Input

Checkbox Selection

Dropdown Value

Modal Visibility

Search Input

Never promote temporary state into the global store.

---

# API Layer

The frontend communicates only with FastAPI.

Architecture

```text id="api001"
Page

↓

Hook

↓

API Service

↓

Axios Client

↓

FastAPI
```

Pages should never perform HTTP requests directly.

---

# Axios Client

A single Axios instance should be shared.

Responsibilities

Base URL

Authentication

Timeouts

Request Interceptors

Response Interceptors

Global Error Handling

---

# API Services

Each module owns one service.

Examples

```text id="api002"
AgentService

DashboardService

ApprovalService

PolicyService

ExecutionService

AuditService

EnterpriseRegistryService
```

These services wrap backend APIs.

---

# DTO Mapping

Backend responses should map to frontend models.

Never expose raw backend structures directly inside components.

Example

Backend DTO

↓

Mapper

↓

Frontend Model

↓

UI Component

This keeps the UI stable if APIs evolve.

---

# Real-Time Communication

WebSockets power live updates.

Use cases

Execution Graph

Approval Notifications

Dashboard Metrics

Execution Logs

System Alerts

Reconnect automatically after disconnects.

---

# Live Execution Events

The frontend subscribes to execution events.

Examples

Node Started

Node Completed

Node Failed

Approval Waiting

Execution Finished

Each event updates the UI immediately.

# Table Standards

React Hook Form

*

Block Agent

Suspend Agent

Disable Firewall Rule

Summary

Configuration

History

Audit

Related Objects

Actions

Users should not lose page context.

---

# Loading Experience

Examples

Dashboard Cards

Tables

Agent Details

Policy Details

Audit View

Execution Details

High Contrast

Light

Dark Mode

Examples

# Empty States

Every feature requires meaningful empty states.

Example

"No Governance Requests Yet"

↓

Description

↓

Primary Action

Never display an empty screen.

---

# Error Boundaries

Major pages should be wrapped with error boundaries.

Failures should not crash the entire application.

---

# Performance Guidelines

Avoid unnecessary re-renders.

Memoize expensive components.

Lazy load large modules.

Virtualize large tables.

Avoid oversized component trees.

Optimize React Flow rendering.

---


---

# Development Principles

1. Pages compose components.

2. Components remain reusable.

3. Hooks own frontend logic.

4. Services own API communication.

5. React Query owns server state.

6. Zustand owns global UI state.

7. Components never communicate directly with FastAPI.

8. Business workflows belong to feature modules.

9. Navigation mirrors business domains.

10. The frontend exists to visualize governance, not hide it.

---

# UI Consistency Rules

Every page should include

Page Title

Description

Toolbar

Primary Content

Loading State

Empty State

Error State

Consistent spacing

Consistent typography

Consistent actions

Users should never need to relearn navigation between modules.

---

# Final Frontend Principle

The SentinelAI frontend is not a generic administration panel.

It is the operational interface for governing autonomous AI agents.

Every page, component and workflow should help administrators:

* Understand governance
* Configure governance
* Observe governance
* Trust governance
* Explain governance
* Audit governance

The interface should transform a complex backend governance engine into an intuitive, transparent and enterprise-grade user experience.
