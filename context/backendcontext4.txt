# SentinelAI Backend Master Context

## Part 4 — REST APIs, Database Design, Execution Lifecycle, WebSockets, Security & Development Standards

---

# Backend API Philosophy

The backend exposes a clean REST API.

The frontend communicates only with FastAPI.

The frontend never communicates with:

* LangGraph
* Services
* Repositories
* Enterprise APIs
* Database

FastAPI acts as the single public interface.

---

# API Categories

The REST APIs are organized into feature modules.

```text
/api/v1

agents/

/policies/

/firewall/

/risk/

/budget/

/compliance/

/enterprise/

/governance/

/approvals/

/audit/

/dashboard/

/settings/
```

Each module owns one business capability.

---

# Governance APIs

The Governance APIs are the most important APIs in SentinelAI.

They are consumed by autonomous AI agents.

Primary endpoint

```text
POST

/api/v1/governance/execute
```

Purpose

Submit an execution intent for governance evaluation.

The API never directly exposes enterprise endpoints.

---

# Governance Execution Lifecycle

Every request follows exactly the same lifecycle.

```text
Receive Request

↓

Validate Payload

↓

Initialize GovernanceState

↓

Execute Governance Graph

↓

Generate Explainability

↓

Build Governance Response

↓

Return Response
```

No shortcuts exist.

---

* Suspend Agent
* Activate Agent
* Block Agent
* Delete Agent
* Get Agent
* List Agents
* Update Trust Score

Purpose

Operations

* Enable Policy
* Disable Policy
* Delete Policy
* View Policy
* Search Policy

Policies should be data-driven.

Not code-driven.

Manage AI Firewall rules.

Operations

* Update Rule
* Delete Rule
* Enable Rule
* Disable Rule
* List Rules

# Database Philosophy

PostgreSQL is the system of record.

The database stores business state.

LangGraph stores execution state.

These are different concerns.

# Security Principles

# Authorization

Administrative users manage SentinelAI.

Agents execute governance requests.

These are separate identities.

Never mix administrator authentication with Agent Passports.

---

# Performance Goals

The backend should optimize for predictable latency.

General principles

Avoid unnecessary database queries.

Cache static configuration when appropriate.

Avoid loading entire entities.

Keep nodes lightweight.

Move heavy business logic into services.

---

# Architectural Invariants

These rules are permanent.

1. FastAPI never contains business logic.

2. LangGraph never contains business logic.

3. Nodes orchestrate only.

4. Services implement business rules.

5. Repositories own persistence.

6. Adapters own enterprise integration.

7. Database entities represent business state.

8. GovernanceState represents execution state.

9. Every request is auditable.

10. Every decision is explainable.

11. Enterprise execution always occurs after governance approval.

12. Every backend feature must conform to this architecture.
